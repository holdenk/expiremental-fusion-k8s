# Fusion on Kubernetes

Deploys the [Fusion](https://github.com/0x2E/fusion) RSS reader with a ClusterIP
Service, optionally with OIDC single sign-on.

## Install

Requires `kubectl` and `curl`.

```bash
./install.sh            # interactive
./install.sh --dry-run  # render to .local/<namespace>/rendered.yaml without touching the cluster
```

Non-interactive, with OIDC:

```bash
PUBLIC_URL=https://fusion.example.com \
ENABLE_OIDC=true \
FUSION_OIDC_ISSUER=https://auth.example.com/realms/main \
FUSION_OIDC_CLIENT_ID=fusion \
FUSION_OIDC_CLIENT_SECRET=... \
FUSION_OIDC_ALLOWED_USER=<your OIDC sub> \
./install.sh --yes
```

`./install.sh --help` lists every setting. Answers are saved in the gitignored
`.local/<namespace>/` directory, secrets included, so re-running only changes what
you change. The pod restarts only if the configuration changed.

## What gets deployed

| Resource | Purpose |
| --- | --- |
| Deployment `fusion` | One replica, non-root, read-only root filesystem |
| Service `fusion` | Port 80 to the app. Type is configurable with `SERVICE_TYPE` |
| PVC `fusion-data` | SQLite database at `/data/fusion.db` |
| Secret `fusion-secrets`, ConfigMap `fusion-config` | Generated by the installer |

## Exposing it

Without any further setup, reach Fusion with
`kubectl -n fusion port-forward svc/fusion 8080:80`, then open
`http://localhost:8080`.

To reach it over Tailscale, see
[Tailscale's Kubernetes docs](https://tailscale.com/docs/kubernetes).

For Tailscale, an Ingress or a load balancer, set `PUBLIC_URL` to the address people
will open. Fusion rejects requests from browser origins not on its allowed list, and
the installer builds that list from `PUBLIC_URL`, so a missing or wrong URL makes
logins fail with 403. If a proxy sits in front of Fusion, set
`FUSION_TRUSTED_PROXIES` to its addresses so that login rate limits apply per client.

## OIDC

- **Register the redirect URI** with your provider. It's
  `https://<host>/api/oidc/callback`, and the installer prints it.
- **Restrict who can log in.** Without `FUSION_OIDC_ALLOWED_USER`, every account at
  the issuer gets in, so the installer requires it unless you set
  `OIDC_ALLOW_ANY_USER=true`. Prefer the OIDC `sub`: Fusion doesn't check
  `email_verified` when matching an email.
- **A password still exists.** Fusion has no way to turn password login off, so the
  installer keeps a strong one, also used for the Fever API. It refuses
  `FUSION_ALLOW_EMPTY_PASSWORD`, because Fusion would then accept an empty password
  at login even with OIDC on.
- **The provider must be up when Fusion starts.** Discovery runs at startup, and
  Fusion exits if it fails. The issuer must also match the provider's exactly,
  including any trailing slash. The installer checks this when it can reach the
  provider.

## Upgrade

```bash
FUSION_VERSION=<image tag> ./install.sh --yes
```

To change the default version, edit the image tag in `deploy/base/deployment.yaml`.

## Uninstall

```bash
kubectl delete namespace fusion  # also deletes the PVC, and all feeds and articles with it
rm -rf .local/fusion
```
